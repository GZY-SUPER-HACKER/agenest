# 设计来源：一套双主题 Token 系统

界面的设计参数来自项目早期的一份重设计规格：浅色为默认（白卡片、细边框、
一个蓝色强调色），深色以**纯黑**为底，而不是深蓝控制台。两套主题共用一份 token。

## 一份 token，两套主题

每个颜色只声明一次，写成 `light-dark(浅色, 深色)`（[`styles.css`](../frontend/src/styles.css)），
由 `<html>` 上的 `color-scheme` 决定哪一侧生效：

- **跟随系统**：不写 `data-theme`，根上是 `color-scheme: light dark`；
- **手动切换**：在 `<html>` 上写 `data-theme="light"` 或 `"dark"`。

所以切换主题是一个属性，没有第二份调色板需要同步。代价是依赖 `light-dark()`，需要
Chrome 123+ / Safari 17.5+ / Firefox 120+。

`index.html` 里有一段内联脚本在首次绘制前读 `csd.theme` 并落 `data-theme`——没有它，深色用户
每次加载都会先闪一下白屏。

## 三条不变的设计约束

1. **一个颜色一个含义，而且颜色不单独承载含义。** 状态永远是「小圆点 + 文字」，不是卡片或行
   左侧的彩色竖条——竖条在所有尺寸上都没有了。
2. **推断不能长得像报告。** `possibly_stale` 用空心圆点、虚线胶囊、独立措辞；只有报告出来的
   状态才用实心圆点和实色填充。
3. **没有装饰。** 不用玻璃拟态、大渐变、装饰图表、伪造进度条；只有卡片、细边框和文字层级。

侧栏是四层（host → harness → project → session）。最上面那层回答的是"活在哪台机器上"——多台
机器时这是第一件要知道的事；底下三层是原来就有的，回答"哪个 harness 在忙""它里面哪个任务在动"，
两层时三个 `claude_code` 跨三个项目就是三行毫无关系的条目。

host 这一层存在的理由全在**空的时候**：一台刚接上、什么都没跑的机器，以前和一台从没配置过的
机器长得一模一样（因为所有分组都是从 session 推出来的，没 session 就没分组），只能 SSH 上去问。
所以"已连接但没有 session"要照常画出来，而且要用文字写明白（"Connected — no sessions running on
it."）——空的分组和渲染 bug 长得一样。

两层来源合并成一棵树，这点容易写错：注册表里一行是**一个 connector**（一台机器跑两个 agent 就是
两行），而 rail 画的一个节点是**一台机器**，否则两个 agent 的机器会把自己的 session 列两遍。节点
的连接状态取该机器上最"活"的那一行（connected → stale → disconnected）——一台机器不可能同时连着
又没连着，让上周卸载掉的 codex connector 把好好的 Claude Code 机器拖成"disconnected"是错的。
`frontend/scripts/check-rail-tree.mjs` 把这两条都钉住了。

session 只报了机器名、但那台机器的 connector 从没注册过（`cpctl session start --host lab-box`）
——这种节点照常分组，但**不给任何连接标记**：有 row 才敢说连接状态，没有就不说。

## 状态色：一个颜色一个问题——「这事有多需要你」

| 颜色 | 含义 | Token |
|---|---|---|
| 绿 | **活着**：running、连接正常、all clear | `--ok` |
| 中性（灰） | 干净地结束了，或者不知道。**默认**，故意不起眼 | `--quiet` / `--surface-2` |
| 琥珀 | interrupted | `--warn` |
| 红 | failed | `--dead` |
| **空心** | 推断出来的，不是报告上来的（`possibly_stale`） | — |

**2026-10-18 修正。** 在此之前 `running` 有自己的蓝色（`--live`），代价是一个颜色承载了两个含
义：详情页的状态胶囊里**绿色表示 completed**，而卡片和侧栏行里 completed 是中性默认（根本
没有规则）。同一个概念三处画法不一致，而且页面上最响的颜色花在了最不需要你的那个状态上。

现在绿色在三个地方都表示「活着」，completed 统一走中性默认——也就是卡片和侧栏一直在用的那个。
`--live` / `--live-soft` 两个 token 已删除。

**2026-10-24 补充：idle。** agent 完成一轮回复、但进程还开着时，状态仍然是 `running`，界面用
中性色写 `idle`。它不是推断（`turn_completed` 是 agent 报的），所以圆点保持**实心**；它也不是
「活着并且在干活」，所以不占绿色。绿色从此只回答一个问题：**它现在在工作吗**。侧栏的 Running
筛选、节点标记、底栏计数和总览的 Running 瓦片都不再把它算进去。

**约束 2 的适用范围也补了一处。** 空心点原本只画在侧栏行上，RUNNING NOW 的卡片**没有**
`data-stale` 规则——它会画一个**实心点**，紧挨着「No activity reported」这行字。那正是约束 2
要防的东西。现在卡片和行共用同一套：`data-stale="true"` → `background: transparent` +
`inset` 描边。

## 切主题时不做颜色过渡

`.card`（`background, border-color`）和 `.chip`（`background, color`）是全 app **仅有**两处定义
了 `transition` 的元素。切主题时其他所有元素瞬间换色，只有这两个花 ~120ms 渐变过去——页面看
起来像撕裂，不像淡入。

修法不是删掉这两个 transition（它们正是 hover/press 手感好的原因），而是在**换色那一帧**把过渡
关掉：`applyTheme()` 调 `suppressColourTransitions()`，给 `<html>` 加 `.theming`，
`styles.css` 里 `.theming * { transition: none !important }`，两个 `requestAnimationFrame` 之后
摘掉。

两个 rAF 而不是一个：这个 class 必须活到浏览器**真的把新配色画出来**为止，而单个 rAF 回调仍可能
早于那次绘制。另外用一个递增的 ticket 防止快速连点两次时，第一次的清理把第二次的过渡提前打开。

## 折叠动效

侧栏三层（host / harness / project）共用一套 disclosure 动效，实现在
[`styles-rail.css`](../frontend/src/styles-rail.css) 的 `.collapse`：

- 展开 240ms、收起 200ms，都用 `--ease-out` = `cubic-bezier(0.2, 0, 0, 1)`。两级时长不同
  不是笔误：展开比收起慢一点点，视觉上"关得干脆、开得从容"。
- 箭头旋转 200ms，和高度同一条曲线，两个一起动才不会散。
- 高度用 `grid-template-rows: 0fr → 1fr` 做，内容高度多少都不用测、不用写死。
- **裁剪在容器上，内容 `align-self: start` 不拉伸**。这不是随意的选择：Chrome 对 `fr` 轨道
  是按容器 *已解析* 的高度再算一次的，所以轨道是 `f²·内容高` 而容器自己是 `f·内容高`，被拉伸
  的包裹层整段动画里都比外面的盒子矮，表现为一条"先张开再合上"的空带。裁剪放在容器上、让内容
  保持自然高度，就变成了从上往下揭开。
- 收起时用 `visibility: hidden`（延迟到动画结束）把子树移出 tab 顺序——0 高度被裁掉的按钮
  依然可以聚焦。注意 `visibility` 允许后代重新声明 `visible`，所以"可见"那条规则必须从根往下
  每一层都写进选择器（host → group → proj），否则关掉的 host 里的 harness 仍会把内容重新点亮。
  这也是"可见"那条不能偷懒写成一个后代选择器的原因。
- `prefers-reduced-motion: reduce` 下直接 `transition: none`（带 `!important`，因为要压过带
  状态的选择器）；全局那条只钳时长，钳不掉 `transition-delay`。

## 设置入口：两页同一个齿轮，同一个组件，同一套内容

两个页面右上角都是齿轮，点开的是**同一个 `SettingsSheet` 组件、同一套分组**：

| | dashboard | agent 页 |
|---|---|---|
| 分组 | Agent / Conversation / Memory / Appearance / This device | 同左 |

- **图标从"太阳/月亮"改成齿轮**。原来 dashboard 是一键切主题的图标、agent 页是齿轮，同一个
  app 的同一个偏好有两个入口、两种交互，读起来像两个设置。
- **一个组件，一套内容**。中间走过两步弯路：先给 dashboard 单独写了个只放 Appearance 的
  面板（两个设置界面，两处会各自漂移）；再改成同一个组件但按页给不同分组（仍然是两套内容，
  用户在 dashboard 上打开会以为设置丢了）。现在两边完全一样。
- **"哪些设置属于哪一页"这个划分被否掉了**。当时的理由是"用哪个 agent"只对对话成立——但
  tab bar 本来就会给另一页上跑着的任务点一个在线小圆点，所以两个 tab 是同一个会话的两个视图，
  不是两个应用。设置跟着会话走，不跟着视图走。
- **面板必须渲染在 `hidden` 的 pane 之外**。它由 `AgentPage` 声明（那是持有 agent 状态的地方），
  但用 `createPortal` 挂到 `<body>`：dashboard 显示时 agent 那个 pane 是 `hidden`，
  `display: none` 的祖先会把面板一起藏掉。用 portal 比把状态从 `AgentPage` 里整个提出来短得多。
- **`--ink-2` 而不是 `--accent`**：`--accent` 在浅色和深色下是同一个值，所以一个蓝色的图标
  是页面上唯一不响应 `data-theme` 的东西。`--ink-2` 是 `light-dark()`，跟着主题走，也和
  `.iconbtn` 一致。

**主题状态的归属顺带理顺了**：它原本同时存在于 `App`（读存储、跟随 OS、应用到 `<html>`）和
`AgentPage`（自己再读一份、自己应用）——两份真相。既然主题写在 `<html>` 上、管着两个页面，
就归 `App` 独有，`AgentPage` 只把它转发给面板。这修掉了一个边界 bug：用户显式选了浅色之后，
`App` 那份仍是 `null`，系统主题一变就会被 `applyTheme(null)` 覆盖掉用户的选择。

代价说清楚：切主题从"一次点击"变成了"点开 + 一次点击"。换来的是一致——两页同一种控件，
同一个位置，同一个含义。这是用户明确要的取舍。

"跟随 OS"这个状态也一起没了：分段控件必须报出当前值，所以它显示 `theme ?? systemTheme()`，
一旦点了就写死一个显式选择。原来那个"翻转到当前显示的反面"的坑（`null === "dark"` 永假，
深色设备用户第一次点之后按钮永久失效）随之一并消失——面向两个选项的控件不需要算反面。

## 气泡配色：用户消息不再是最响的那块

浅色主题下用户气泡原本是 `#303030` 配白字——一整块近黑，是页面上最响的东西。长 prompt 变成
一大片深色，和它换来的那条回复抢注意力。现在改成：

| | 浅色 | 深色 |
|---|---|---|
| 用户 | `#e4e6ea` + `#1d1d1f` | `#3a3a3e` + `#f5f5f7` |
| agent | `#f0f0f0` + `#303030` | `#1c1c1f` + `#e8e8ea` |

用户气泡和 agent 气泡是**同一个灰family，只差一档**，所以整段对话读起来是一件事，
"谁在说话"只由左右位置和缺角承载。深色主题本来就是这个关系（用户那侧更亮），保留不动——
"更靠近前景"在两套主题里是同一个关系，只是它恰好一个朝上、一个朝下。

## 时间：气泡上没有钟，分隔符上有

气泡底部原本常驻一条时间（每条消息一条，后来改成每组最后一条一条）。两种都还是"日志"，不是
"对话"：时间属于**一段对话发生的那个时刻**，不属于某一条消息。现在改为只在需要定位的位置画一个
居中的分隔符，气泡本身不带时间：

- **首条消息**：`Today · 10:31`，日期加时间。对话的开头是读者唯一会问"这些是多会儿的事"的地方。
- **跨自然日**：只画日期（`Yesterday`、`Oct 12`，跨年时带年份）。日期**取代**这一位置的时间，
  而不是和时间叠在一起——两个标签说同一件事。
- **同一自然日内间隔超过 5 分钟**：画时间（`10:31`）。
- **其余情况**：不画。连续几条消息属于同一个时刻。

间隔比较的是真实时间差（毫秒），不是分钟数的差：`23:59 → 00:01` 是两分钟。用用户本地时区格式化。

**气泡之间只有间距，没有"同组"样式了。** 同侧连续消息原本会收紧间距、共用一条直角边，读成"一次
说完的话"。但 agent 现在会连续发 checkpoint 和回答，那是两条独立陈述；粘在一起会糊成一块（用户
2026-10-20 的反馈）。现在所有气泡都保留完整圆角，同侧相邻 8px、换人说话 12px（都再叠加容器
本身的 2px 间隙）。分隔符出现时不需要再"重置分组"——已经没有分组了。

**间隔在"对话消息"之间算，工具行不参与。** 工具行是过程，不是新的时刻：它自己不带分隔符，也不
推进时钟。这样"显示 agent 过程"这个开关不会挪动任何分隔符——显示偏好不该改变时间报在哪里。
分隔符是渲染时从 `messages` 推导的（`useMemo`），不落库、不缓存，因此历史加载、
断线重连后的重取、流式追加都自然得到正确结果。

**分隔符从 pill 改成了小字 + 两侧极细线。** pill 是一个 surface，而 surface 读起来像气泡的一部分；
分隔符不属于任何一方，所以框住它的是居中和对比度，不是背景。分隔线只占文字两端的固定短长度，
不横贯整行——它给文字加框，不是把列表切开。

## Checkpoint：不再有专属样式

进度 checkpoint 原来是一条没有气泡的灰字 + 左侧竖线，用"看起来不像回答"来保证它不会被误读。
但这个样式依赖的数据只有一部分后端能提供：native 和 nanobot 的 websocket 门有，openclaw、hermes
没有；而协议只吐一整段文本的 agent 连 checkpoint 这个概念都没有。结果是同一个页面，在有的 agent
上画 stage line，在另外的 agent 上从问题直接跳到回答。

所以 checkpoint 统一按普通 agent 气泡渲染：同样的左侧对齐、同样的圆角、同样的分组规则。工具行
仍然单独成行，因为它依然是"发生的事件"而不是"说出来的话"。

代价说清楚：checkpoint 从外观上不再与回答有区别。"还在干活"这件事由工具行承担——对另外三个
agent 来说，它本来就一直由工具行承担（docs/design.md §23）。

### dashboard 时间线里的 checkpoint 是另一个概念

上面说的是 agenest 对话里的 checkpoint：模型写的一段话，按普通气泡渲染。dashboard 的
`checkpoint` 事件是 **session 时间线**上的一行，来自 coding agent 自己写的一句话
（docs/design.md §37）。它不画成气泡，也不进入 status pill：

- 圆点用空心 accent，和 turn boundary 一样——它是"在干活"，不是"结果"；
- 正文用 `--ink`，因为它是 agent 对读者说的话，不是机器行；`progress` 仍然用 `--ink-2`；
- payload 里的 `message_id` 不显示，它是幂等键，不是读者需要的信息；
- 它不进入 needs-attention，也不改变 status；`idle` 会被它清掉（有 checkpoint 就说明又开始干活了）。

没有 checkpoint 的 session 不显示任何占位。"这个 agent 没有中间报告"是诚实的，用工具名或耗时
补一句话不是。

## 附件：卡片，不是链接

文件在对话里是**卡片**，不是一行带下划线的链接。卡片把三个问题一次答完：这是什么（名字 +
图标/缩略图）、多大、点一下会发生什么（打开或下载）。链接只能答第一个，而手机上没有 hover，
用户没法先悬停确认。

- **两个动作，不是一个按钮猜。** 点卡片本身 = 交给系统分享面板（`navigator.share`，选一个
  App 打开）；右侧箭头 = 下载到本机。浏览器没有 share API 时，点卡片退化为下载，而不是一个
  什么也不做的按钮。
- **图片直接显示，其他都是文件卡。** 图片在气泡里就是内容，不需要先点一下才知道是什么；非图片
  的缩略图没有信息量，占位图反而比文件名更吵。
- **颜色从气泡继承。** 用户那侧和 agent 那侧的底色不同，卡片若自带一套 token 就会在其中一侧
  不可读。所以名称、图标用 `currentColor`，次要信息（大小）用 `opacity` 而不是 `--ink-3`——
  那个 token 是给页面底色调的，不是给气泡调的。
- **输入框里待发送的文件是 chip，在胶囊上方。** 不塞进输入框：那会挤压文字宽度，而且"删除一个
  待发送文件"需要和"编辑文字"是两次不同的点按。`×` 只有 20px，是因为它紧挨着手指刚点过的
  区域，不需要再大；但它是独立按钮，不会误触发送。
- **`+` 在胶囊外面，和发送键左右对称。** 放进去会让胶囊不再是胶囊，也把两个完全不同的动作
  （附加、发送）放进同一个视觉容器里。
- **菜单是输入框上方的小浮层，不是 sheet。** 它只有两个选项，且都通向系统选择器；一个从底部
  升起的全屏 sheet 会让"选图片还是选文件"这个一秒就能完成的选择变成一次导航。

## 排队与中断：发送键不改变含义

agent 在跑的时候，输入框仍然能打字、仍然能发送。发送键**不变成**停止键——那个写法让"再说
一句"必须以取消正在写的回答为代价。现在忙时发送 = 入队，停止是旁边的第二个按钮。

- **队列在胶囊上方，和待发送文件同一层。** 一条消息在真正发出去之前不属于对话记录，所以它
  不画成气泡；画成气泡会让读者以为 agent 已经看到了。虚线边框就是这个意思：还没有到对面。
- **每条都带 `Queued` 标签和一个 ×。** 标签回答"它发了吗"，× 回答"我能收回吗"。收回是用户
  的动作，所以它必须是一次独立的点按，而不是长按或滑动。
- **一次只放一条。** 回合结束才发下一条，否则两段回答会交错。**停止会释放队列**——这就是
  interrupt 的语义：打断当前回答，排队的话接着说，而不是一起丢掉。
- **tab 上的小绿点只表示未读。** "agent 在跑"也点着绿点，等于整段运行期间一直亮着，看完也
  不灭——它没有告诉读者任何页面上看不到的东西。现在只有 agent 在你看着 dashboard 时说了话
  才亮，进 agent 页就灭。工具行不算，checkpoint 算（那是 agent 在对读者说话，不是机器日志）。

## 设置里的子页：齿轮进，返回箭头出

agenest 那一行右侧的齿轮打开的是**同一个 sheet 里的子页**，不是第二个弹窗：标题换成
「agenest settings」，左上角出现返回箭头，右上角的 × 仍然关闭整个设置。理由和本文开头那条
一样——设置只有一个表面；两个叠起来的 modal 各自要处理焦点、Escape 和滚动，而手机上的人
看不出自己在第几层。

- **一行两个动作时，行变成容器。** 整行仍然是「切到这个 agent」，右侧 46px 是齿轮，中间一条
  分隔线。不是嵌套 button（HTML 不允许），也不是把切换挤成一个小圆点——那两种都会让一次点按
  的含义取决于落点差了几毫米。
- **表单字段用块，不用行。** `srow` 是「标题 + 副标题 + 一个控件」，适合开关；输入框需要整行
  宽度，标签放上面、提示放下面。把标签当占位符的写法被否掉了：它恰好在字段有值时消失，而那
  正是人在核对自己输入的时刻。
- **空字段的占位符写的是环境变量。** 「留空 = 继承」这句话必须在输入框里就说清楚，否则清空
  看起来像丢数据。清空全部、撤销授权这类动作仍然是两次点按。

## 发送即出现、切换即转圈

- **按发送，气泡立刻在对话里。** 输入框清空而页面不变，是「按钮没反应」的形状。新气泡先用用户
  自己的样式画出来，稍淡一点表示还在路上；agent 自己的那一行回来就替换它，POST 和 stream 谁先
  到都一样。失败的消息**留在原处**并写「Not sent」——删掉它，等于说消息发出后又悄悄消失了。
- **排队中的消息仍然不是气泡。** 它还没发出去，画成气泡就是把话塞进 agent 嘴里（见上一节）。
- **三个点在 agent 干活时一直有。** 之前只要有工具在跑点就让位，可「过程」视图关着时那一行根本
  不画，于是每条命令执行期间页面一片安静。现在只有**画出来的**工具行才能替换掉那三个点；标题栏
  同理，过程关着时只说「typing…」，不说用户选择不看的命令名。
- **切换 agent 时中间是转圈，不是空对话。** 切换一开始就清掉上一个 agent 的记录（留着会被读成
  「我的消息没同步」），位置交给一个转圈：一个还在下载的对话不是「什么都没说过」。首屏加载用同
  一个状态，所以刷新也不会先闪一下空状态。切换失败会把原来的对话装回去，且切换途中发不了消息。

## 已知取舍

- 深色不是 Telegram 调色板，浅色也不是。`docs/design.md` 里凡是提到"取自 Telegram 源码"的
  段落只对**信息架构**（三层侧栏、状态语义）成立，对配色已经过期。
- 参考稿里侧栏一行为两层（项目名当标题），这里保留了现有的三层结构，因为拆掉项目层属于改功能，
  不属于改样式。
